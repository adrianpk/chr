# Use The Dev To Main Gate With Woodpecker

This guide wires the Chryso promotion gate into a Woodpecker pipeline.

## Preview The Workflow

From the managed project root:

```sh
chr gate woodpecker init --dry-run
```

Review the generated YAML before writing it.

## Create The Workflow

When the project does not already have a Woodpecker workflow:

```sh
chr gate woodpecker init
```

This writes:

```text
.woodpecker.yml
```

The generated step installs `chr`, fetches `origin/main`, and runs:

```sh
chr gate dev-main --dir . --base ${CHR_GATE_BASE:-origin/main} --head ${CHR_GATE_HEAD:-HEAD}
```

## Existing Workflow

If `.woodpecker.yml` already exists, the command prints the generated snippet
and leaves the existing file unchanged.

Use `--write` only for files previously generated by Chryso:

```sh
chr gate woodpecker init --write
```

Unmarked existing files are refused so that hand-written Woodpecker pipelines
are not rewritten accidentally.

## Configure Gate Policy

Optional project policy lives at:

```text
.chr/default/config/gates.yml
```

Example:

```yml
gates:
  dev_main:
    validation_command: make verify
    traceability:
      mode: agent_only
      fail_on_missing_agent_evidence: true
      warn_on_manual_changes: false
    manual_changes:
      list: true
      warn_on_high_risk_paths: true
    high_risk_paths:
      - internal/runtime/**
      - .woodpecker.yml
```

## Read The Result

Woodpecker marks the pipeline failed when the gate exits non-zero.

Detailed local evidence is written under:

```text
ops/default/report/<id>/ (Markdown in artifact.md, JSON in evidence/gate-report.json)
```

Read the Markdown report for human review and the JSON report for automated
checks.
