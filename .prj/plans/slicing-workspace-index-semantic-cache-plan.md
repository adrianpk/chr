# Workspace Index And Semantic Cache Slicing Plan

Status: active

## Purpose

Plan the evolution from the current ephemeral `WorkspaceGraph` into a local
workspace index that behaves like a poor-man's graph/read model over the
filesystem.

The durable source of truth remains Markdown files. The runtime may keep a
structural index in memory for navigation, validation, relationships, and
suggestions. A separate semantic digest layer may use an LLM to create compact
agent-oriented retrieval hints, but those digests must be cached by source hash
so restarting the TUI does not require expensive regeneration.

Conversation decisions:

- There is no database-backed source of truth for Project and Cases.
- Filesystem Markdown remains durable truth.
- The runtime should have a richer in-memory workspace index.
- The index should provide graph-like lookup and relationship traversal without
  becoming a persistent database.
- The index should support use-case suggestions and future autocomplete-style
  selectors in the TUI.
- Direct user edits to files are valid and must be detected.
- Structural indexing must be deterministic and local.
- LLM-assisted semantic indexing is optional, incremental, and cache-backed.
- Semantic digests are not human-facing labels; they are dense retrieval hints
  useful for agents and search.
- Cache artifacts are discardable and must not become authoritative.
- `Draft` should not remain a first-class document type. Rough material is a
  dump, quiz answers can help synthesize a spec, and specs may carry a `draft`
  status when they need review.

## Current State

The delivered Markdown-only workspace model provides:

- Markdown-backed Project and Case metadata;
- an ephemeral `WorkspaceGraph`;
- graph-based Project and Cases TUI projection;
- graph rebuild on refresh and after app writes;
- lazy body reads for context assembly;
- unresolved reference diagnostics.

This is enough for navigation and context assembly, but it is still closer to a
lightweight graph projection than to a full application read model.

The current implementation and documentation still contain historical draft
language in authoring and command references. That language conflicts with the
current direction that dumps and quizzes are source material, while specs are
the formal artifact and can use a draft status.

## Target Model

The target model is:

- Filesystem Markdown is the only durable source of truth.
- `internal/chc` owns the workspace index model and deterministic scanner.
- The structural index is loaded at startup and rebuilt or incrementally updated
  after detected file changes.
- The structural index contains nodes, edges, lookup maps, diagnostics, source
  paths, modified times, and source hashes.
- The structural index does not store full document bodies by default.
- Document bodies are read lazily when a detail view, context assembler, or
  semantic digest worker needs them.
- `internal/chcapp` exposes stable service queries over the index.
- TUI, CLI, and future adapters consume service queries instead of parsing
  workspace files directly.
- Semantic digests are generated by an optional LLM worker and cached under a
  discardable workspace cache path.
- Semantic digest cache keys include schema version, model, prompt hash, and
  source hash.
- TUI startup does not block on semantic digest generation.
- Missing or stale semantic digests are reported as index health, not as a hard
  failure.
- Draft-specific commands, surfaces, and document-family references are removed
  or migrated to dump/quiz/spec language.

## Proposed Model Shape

The structural index should keep entity and relationship data explicit.

```go
type WorkspaceIndex struct {
    NodesByID   map[string]WorkspaceNode
    NodesByPath map[string]string
    Edges       []WorkspaceEdge
    ByKind      map[WorkspaceNodeKind][]string
    ByCaseSlug  map[string][]string
    Diagnostics []WorkspaceDiagnostic
    BuiltAt     time.Time
}
```

```go
type WorkspaceNode struct {
    ID          string
    Kind        WorkspaceNodeKind
    Slug        string
    Key         string
    Title       string
    Description string
    Status      string
    CaseSlug    string
    Path        string
    SourceHash  string
    ModifiedAt  time.Time
}
```

```go
type WorkspaceEdge struct {
    From string
    To   string
    Kind WorkspaceEdgeKind
}
```

The semantic layer should be separate from the structural index.

```go
type SemanticDigest struct {
    NodeID       string
    SourceHash   string
    SearchTerms  []string
    Aliases      []string
    Concepts     []string
    Decisions    []string
    Constraints  []string
    RelatedSlugs []string
}
```

## Cache Model

Cache path should be discardable and local to the project.

Candidate path:

```text
.chc/tmp/cache/workspace-index/
```

Expected files:

```text
manifest.json
structural-index.json
semantic-digests/<source-hash>.json
```

Cache invalidation inputs:

- source path;
- source hash;
- semantic digest schema version;
- semantic prompt hash;
- semantic model id.

## Refresh Model

Refresh should have several layers:

- startup load from cache when valid;
- startup filesystem scan to catch changed files;
- explicit `r` refresh in TUI;
- automatic periodic refresh while TUI is running;
- post-write refresh or targeted index update after service operations;
- optional filesystem watcher later, outside the first implementation pass.

Structural refresh must be local and deterministic. Semantic refresh must be
background-capable and avoid blocking the primary UI.

## Draft Elimination Model

`Draft` should be removed as a document kind and UI/document family.

The document flow should be:

```text
dump
quiz
dump + quiz -> spec
spec(status=draft) -> spec(status=accepted/final)
spec -> plan
```

Implications:

- no `.chc/drafts/` as a new first-class output target;
- no `Drafts` TUI tab or document family;
- no `chc draft` command surface in the target model;
- no `quiz-to-draft` promotion as the desired workflow;
- spec generation may preserve roughness by writing a spec with `status:
  draft`.

Historical docs may remain only when explicitly marked as historical or
superseded.

## Out Of Scope

This slicing does not include:

- introducing Dgraph or any external graph database;
- making cache files authoritative;
- adding embeddings or vector search;
- requiring a daemon for local indexing;
- requiring filesystem watchers in the first pass;
- building a full text editor in the TUI;
- changing ticket execution semantics;
- changing release/versioning workflow;
- invoking an LLM during normal tests.

## Numbering Rule

Slice numbers are local to this slicing and start at `Slice 1`.

Do not continue from Markdown-only workspace model, TUI navigation, service
consolidation, or previous PR numbers.

### Slice 3: Index Load And Refresh Semantics

Expected report: `.prj/reports/slices/workspace-index-semantic-cache/slice-3-index-refresh-semantics.md`

### Slice 4: Discardable Structural Cache

Status: planned.

Expected branch: `feat/slice-4-structural-index-cache`
Expected PR title: `feat(slice-4): structural index cache`
Expected report: `.prj/reports/slices/workspace-index-semantic-cache/slice-4-structural-index-cache.md`

Goal:

Persist a discardable local cache for the structural index to reduce startup
cost without becoming authoritative.

Candidate scope:

- define cache manifest schema;
- write `structural-index.json` under `.chc/tmp/cache/workspace-index/`;
- load cache when schema and source hashes remain valid;
- fall back to filesystem rebuild when cache is missing or stale;
- add maintenance or debug visibility for cache state where practical;
- add tests for cache hit, cache miss, stale cache, and cache deletion.

Expected outcome:

- restarting the TUI can reuse local structural cache while preserving
  filesystem truth.

### Slice 5: Semantic Digest Cache Contract

Expected branch: `feat/slice-5-semantic-digest-cache`

## Validation Strategy

Each implementation slice should run the smallest relevant package tests plus
`make verify` before PR.

Expected common validation:

```text
make verify
```

Semantic indexing tests must not call a real LLM. Use fake generators and
fixture cache entries.
